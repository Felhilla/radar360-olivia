Esquema técnico · Canvas

Colección canvas en public.registros. Un registro por fila de la Matriz: id = matrizId. GET lista; PUT reemplaza un canvas y exige trigger:true y editadoPor; DELETE recibe {id}. El último guardado prevalece.

{ id, matrizId, cliente, sector, problema, oferta,
  aliado: { tipo: "actor" | "gremio", id, nombre,
    cuadrante?: { id, nombre }, promedio?: number } | null,
  buyer, sponsor, ruta90, rutaAuto: boolean, cta,
  horizonte: "30" | "60–90" | null,
  editadoPor, updatedAt: "ISO 8601" }

cliente, sector, problema y oferta son una copia de la Matriz al guardar; no se editan aquí. horizonte conserva la regla aplicada, incluso con ruta manual. Sin aliado, queda sin horizonte. Se permiten campos pendientes. Límites: nombre 60, buyer/sponsor 300, CTA 1000 y ruta 4000 caracteres. Las reglas se leen de canvas-config.json.

Conexión con Herramienta 5 · esquema de datos

GET /api/priorizacion-votos?resumen=1 devuelve un arreglo JSON (vacío si no hay calificaciones). Cada elemento tiene exactamente esta forma:

{
  "actorId": "mercados-ejemplo",
  "nombre": "Actor de ejemplo",
  "categoria": "mercados",
  "sector": "Servicios",
  "indiceImpacto": 4.25,
  "indiceEsfuerzo": 2.50,
  "cuadrante": {
    "id": "victorias-tempranas",
    "nombre": "Victorias tempranas"
  },
  "votos": 3
}

actorId, nombre, categoria, sector y los campos de cuadrante son cadenas. Categoría: competidores, mercados, aliados o autoridades. Índices: números entre 1 y 5, redondeados a dos decimales (JSON puede omitir ceros finales). Votos: entero positivo. Cada persona pesa igual: se promedian sus índices ponderados completos; no se guardan calificaciones parciales.

La clasificación usa el promedio sin redondear y considera alto un índice mayor o igual al umbral. Los actores descartados o eliminados se excluyen; los ocultos del Radar conservan su resultado para la Herramienta 5. Esta pantalla y su CSV muestran solo actores visibles del Radar y respetan el filtro de categoría.

La fuente única es GET /api/priorizacion-votos?criterios=1: criterios, pesos, escalas, umbral y cuadrantes. GET /api/priorizacion-votos devuelve votos completos. PUT reemplaza el voto identificado por actor y nombre; DELETE recibe {actorId, votante}. Sin autenticación, como Gremios.

Nota metodológica: el Excel menciona una redistribución para «no aplica» que el documento no desarrolla. Se exigen diez respuestas de 1 a 5, sin redistribución. Si no tienes información suficiente, deja ese actor sin calificar.
