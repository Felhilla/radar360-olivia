Conexión con Herramienta 5 · esquema de datos

GET /api/priorizacion-votos?resumen=1 devuelve un arreglo JSON (vacío si no hay calificaciones). Cada elemento tiene exactamente esta forma:

{
  "actorId": "mercados-ejemplo",
  "nombre": "Actor de ejemplo",
  "categoria": "mercados",
  "sector": "Servicios",
  "indiceImpacto": 4.25,
  "indiceEsfuerzo": 2.50,
  "cuadrante": {
    "id": "victorias-tempranas",
    "nombre": "Victorias tempranas"
  },
  "votos": 3
}

actorId, nombre, categoria, sector y los campos de cuadrante son cadenas. Categoría: mercados (Empresas) o aliados (Gremios-aliados). Índices: números entre 1 y 5, redondeados a dos decimales (JSON puede omitir ceros finales). Votos: entero positivo. Cada persona pesa igual: se promedian sus índices ponderados completos; no se guardan calificaciones parciales.

La clasificación usa el promedio sin redondear y considera alto un índice mayor o igual al umbral. Solo se incluyen actores activados y vigentes, aunque estén ocultos del Radar. La pantalla y el CSV respetan el filtro de grupo. Victorias tempranas y Apuestas estratégicas pasan a la Actividad 5.

La fuente única es GET /api/priorizacion-votos?criterios=1: criterios, pesos, escalas, umbral y cuadrantes. GET /api/priorizacion-votos devuelve votos completos. PUT reemplaza el voto identificado por actor y nombre; DELETE recibe {actorId, votante}. Sin autenticación, como Gremios.

Nota metodológica: el Excel menciona una redistribución para «no aplica» que el documento no desarrolla. Se exigen diez respuestas de 1 a 5, sin redistribución. Si no tienes información suficiente, deja ese actor sin calificar.

Conexión con Herramienta 4 · esquema de datos

Este sitio guarda los actores en Netlify Blobs a través de la función /api/actors (GET lista, POST agrega, PATCH edita). Cualquier persona con el link puede leer y escribir, sin invitación ni cuenta.

{ id, nombre, categoria: "competidores"|"mercados"|"aliados"|"autoridades", sector, confianza: "alta"|"media"|"baja"|"por_identificar", estado: "verificado"|"por_validar"|"agregado_taller"|"descartado", mostrarEnRadar: true|false, origenTaller: true|undefined, justificacion, createdAt, updatedAt }

La Herramienta 4 debe leer los actores con mostrarEnRadar !== false y estado !== "descartado" — esa es la lista final que efectivamente aparece en el radar y la que debe calificar en interés/influencia. Puede leerlos directamente con GET /api/actors sobre este mismo sitio.
